# GOV.UK RAG Assistant

An Azure-native assistant that answers staff questions about UK employee-rights guidance (leave,
sick pay, flexible working). Every answer cites its GOV.UK sources, and it says "I don't know" when
the documents don't cover a question.

> Work in progress: currently at **Milestone 5 (Azure deployment)**.

## Local development

Requires [uv](https://docs.astral.sh/uv/).

```sh
uv sync                                   # install dependencies
uv run uvicorn govuk_rag.main:app --reload   # chat page and API on http://127.0.0.1:8000
```

### Checks

```sh
uv run ruff check .          # lint
uv run ruff format --check . # formatting
uv run pyright               # type check (strict on src/govuk_rag)
uv run pytest                # tests
```

### Configuration

Settings come from environment variables prefixed `RAG_` (or a local `.env` file). See
[`.env.example`](.env.example).

## Deploy to Azure

One command creates every Azure resource, deploys the app and loads the guidance.

**You need:**

- The [Azure Developer CLI](https://aka.ms/azd) (`azd`) and [uv](https://docs.astral.sh/uv/).
  The image is built in Azure Container Registry, so Docker isn't needed, unless your
  subscription blocks registry builds (`TasksOperationsNotAllowed`, common on free-trial and new
  pay-as-you-go subscriptions). azd then builds locally, so have Docker Desktop running.
- An Azure subscription where you can create role assignments (**Owner**, or **Contributor**
  plus **User Access Administrator**), with access to Azure OpenAI.

```sh
azd auth login
azd env new govuk-rag-dev                # any name; it prefixes the resource group
azd env set AZURE_LOCATION uksouth
azd up
```

`azd up` does four things:

1. **Provisions** [`infra/`](infra) (Bicep): Container Apps, Container Registry, Blob Storage,
   AI Search, Azure OpenAI (a `chat` model and `text-embedding-3-small`, both on Global Standard
   deployments, so prompts may be processed outside the chosen region), Log Analytics and a
   managed identity. Key-based access is turned off on Storage, Search and OpenAI. The app uses
   its managed identity, and your own account gets the roles it needs for ingestion.
2. **Loads the guidance**, through the `postprovision` hook
   ([`scripts/load-guidance.ps1`](scripts/load-guidance.ps1) or
   [`.sh`](scripts/load-guidance.sh)). This runs fetch, upload and ingest, and retries while new
   role assignments take effect.
3. **Builds** the image in the registry.
4. **Deploys** it to Container Apps and prints the URL.

**The demo key** is generated by azd on the first provision and passed to the app as a Container
Apps secret. azd keeps it in its local secret vault, and `.azure/<env>/config.json` holds only a
reference to it. To read it, open the container app in the Azure portal, go to **Settings →
Secrets** and show `demo-key`. To share access, send `https://<app-url>/#key=<demo-key>`.

Re-running `azd up` is safe. `azd deploy` only ships code changes.

**Options**, set with `azd env set <NAME> <value>` before `azd up`:

| Name | Default | Use |
| --- | --- | --- |
| `AZURE_SEARCH_LOCATION` | `AZURE_LOCATION` | Put AI Search in another region if free-tier capacity runs out |
| `AZURE_SEARCH_SKU` | `free` | `basic` if the subscription already has its one free search service |
| `AZURE_CHAT_MODEL` / `AZURE_CHAT_MODEL_VERSION` | `gpt-4.1-mini` / `2025-04-14` | Any chat model available in your region |
| `SKIP_GUIDANCE_LOAD` | `false` | `true` to provision without loading the GOV.UK guidance |

**Cost when idle** is close to nothing:

- Container Apps scales to zero.
- AI Search is on the free tier.
- OpenAI is pay-per-token.
- Storage and Log Analytics cost pennies at this size.
- The one fixed cost is the Basic container registry, about £4 a month.

`azd down --purge` deletes everything. `--purge` also removes the soft-deleted OpenAI resource, so
the name can be reused.

**To run locally against Azure:** run `azd env get-values > .env`, add a `RAG_DEMO_KEY=...` line,
then start the app with `uvicorn` as above. Your account already has the roles it needs.

## Ingestion

Guidance flows GOV.UK → Blob Storage → chunk + embed → Azure AI Search. `azd up` runs these steps
for you. To run them by hand, with the `RAG_*` endpoints in `.env`:

1. **Fetch** the pages listed in [`data/govuk_pages.txt`](data/govuk_pages.txt) from the GOV.UK
   Content API. Multi-part guides become one document per part, so citations link to the exact
   section.

   ```sh
   uv run govuk-rag-fetch            # writes JSON documents to data/govuk/
   ```

2. **Upload** them to the Blob container. Every file is checked first, so a bad file uploads
   nothing:

   ```sh
   uv run govuk-rag-upload           # data/govuk/**/*.json → the govuk-guidance container
   ```

3. **Index** them. This creates the search index if needed, then syncs it with the container:

   ```sh
   uv run govuk-rag-ingest
   ```

   Re-running is safe. Unchanged documents are skipped and not re-embedded. Changed documents
   have their chunks replaced, and documents deleted from the container are removed from the
   index. Chunk ids are deterministic, so re-running never creates duplicates.

Ingestion signs in with `DefaultAzureCredential` (`azd auth login` or `az login`). The identity
running it needs these roles. `azd up` grants them to whoever runs it:

- **Storage Blob Data Contributor** on the storage account. **Reader** is enough if you only
  run ingest.
- **Search Index Data Contributor** and **Search Service Contributor** on the search service.
- **Cognitive Services OpenAI User** on the OpenAI resource.

Other data sources plug in by implementing `SourceConnector` (`src/govuk_rag/ingestion/connectors.py`).

## Answering

`POST /chat` takes `{"question": "..."}` and returns an answer with citations, or a fixed
"I don't know" reply:

1. **Retrieve.** One hybrid (keyword + vector) query to Azure AI Search returns the top
   `RAG_RETRIEVAL_TOP_K` chunks. Each chunk is scored by the cosine similarity between the question
   and the chunk. Hybrid search's own score only reflects rank, so a threshold can't use it.
2. **Gate.** Chunks below `RAG_RELEVANCE_THRESHOLD` (default 0.35) are dropped. If none are left,
   the service answers "I don't know" without calling the model. The default was checked against
   the live index with `text-embedding-3-small`. Covered questions scored 0.58 to 0.77 on their
   best chunk, related but uncovered ones (asking for a pay rise) 0.46 to 0.50, and off-topic ones
   (passports, recipes, football) 0.23 or less. So 0.35 turns away off-topic questions cheaply,
   and leaves the model to decline the related-but-uncovered ones.
3. **Answer.** The model (`RAG_CHAT_DEPLOYMENT`, capped at `RAG_MAX_OUTPUT_TOKENS`) is told to
   answer only from the numbered sources, to cite them as `[1]`, and to reply `NO_ANSWER` when they
   don't answer the question. A reply containing `NO_ANSWER` becomes the same "I don't know"
   reply, even if the model explained itself first.
4. **Cite.** Citations list the sources the answer cites, renumbered in order of use, each with
   its page title, GOV.UK link and a snippet.

`/chat` needs `RAG_AZURE_SEARCH_ENDPOINT` and `RAG_AZURE_OPENAI_ENDPOINT`. Without them it returns
HTTP 503. Your identity needs **Search Index Data Reader** on the search service and
**Cognitive Services OpenAI User** on the OpenAI resource.

## Chat page and access

The chat page is served at `/`. It's a single HTML page with its own script and stylesheet, and no
build step.

`/chat` is protected by a shared demo key, sent in the `X-Demo-Key` header:

- Set it with `RAG_DEMO_KEY`. Locally, put it in `.env`. When deployed, it's a Container Apps
  secret.
- Requests with a missing or wrong key get HTTP 401. If no key is configured, `/chat` rejects
  every request with HTTP 503, so a missing secret never leaves it open.
- The page asks for the key and keeps it in the browser's local storage. To share a link that
  fills the key in, use `https://<host>/#key=<demo-key>`. The part after `#` is never sent to
  the server, so the key stays out of server logs, and the page removes it from the address bar.
- `/health` and the page itself need no key.

The page loads nothing from other sites and has no inline code, so it is served with a strict
Content-Security-Policy. Answers are added as plain text, never as HTML.
